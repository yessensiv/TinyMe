# Подключение облачного режима

[← MyRoom](../README.md)

Гостевой режим работает без Supabase. Полный локальный запуск без облака описан в [README](../README.md#быстрый-старт). Этот документ описывает необязательное облачное окружение.

## 1. Подготовь базу

В новом проекте Supabase выполни SQL-файлы из [supabase/migrations](../supabase/migrations) по порядку:

1. `001_core.sql`
2. `002_wallet_ordering.sql`
3. `20261023191637_music_library.sql`
4. `20261023192405_music_upload_quota.sql`
5. `20261023194515_furnished_studio.sql`
6. `20261024064821_room_appearance.sql`
7. `20261024065247_furniture_color.sql`
8. `20261024081200_quiet_evening_collection.sql`
9. `20261024082200_tabletop_placement.sql`
10. `20261024084930_shelf_surfaces.sql`
11. `20261024085957_gaming_collection.sql`
12. `20261024095742_background_sessions.sql`
13. `20261024111602_music_content_hash.sql`
14. `20261112090000_auth_roles.sql`

Для серверных обработчиков входа установи `SUPABASE_SERVICE_ROLE_KEY` в серверном окружении Next.js. Не публикуй его через `NEXT_PUBLIC_`. Миграция ролей добавляет неизменяемые логины и таблицу прав; существующие пользователи сохраняют вход по email. Первый администратор назначается владельцем базы через `user_profiles`, последующие — через `/admin`. Публичная регистрация всегда создаёт обычного пользователя.

Миграции создают таблицы, каталог, RPC, ограничения доступа и приватное хранилище музыки. Для существующего окружения сначала проверь уже применённые миграции; повторно выполнять всю последовательность не нужно.

## 2. Подключи музыкальную библиотеку

Разверни Edge Function **`music-library`** из [исходника](../supabase/functions/music-library/index.ts).

Текущая функция самостоятельно проверяет bearer-токен через `auth.getUser`; встроенная проверка JWT на шлюзе для этого варианта отключена. Окружению функции нужны `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Привилегированный ключ используется только на сервере — в `.env.local` веб-приложения его добавлять не нужно.

## 3. Настрой вход и приложение

В Supabase Auth разреши вход по email и добавь адрес запуска в разрешённые redirect URL: `http://127.0.0.1:3000` (и `http://localhost:3000`, если используешь его). Для опубликованного приложения нужен его собственный адрес.

Скопируй [.env.example](../.env.example) в `.env.local` и укажи URL проекта и публичный клиентский ключ. Перезапусти сервер разработки.

После входа проверь сохранение комнаты после перезагрузки, покупку предмета и загрузку небольшого MP3/WAV. Доставку письма и возврат по ссылке входа нужно проверить с реальным почтовым ящиком.

## Где хранятся данные

| Данные | Гость | После входа |
| :--- | :--- | :--- |
| Комната, инвентарь, монеты | localStorage | PostgreSQL |
| Аудиофайлы | IndexedDB | Приватный Supabase Storage |
| Плейлисты | Браузер | PostgreSQL |
| Музыкальная статистика и настройки плеера | Браузер | Браузер |

Гостевая комната и облачный аккаунт независимы. Автоматического переноса локального баланса, предметов и файлов нет.

## Ограничения музыкального облака

- До **200 файлов**, **1 ГБ** суммарно, **50 МБ** на файл; до **30 плейлистов** и двух незавершённых загрузок одновременно.
- Подписанная загрузка резервирует 50 МБ на три часа. Поэтому даже небольшие файлы временно занимают больше места в квоте; массовая загрузка ограничена.
- Просроченные временные записи очищаются при обращении владельца к библиотеке; отдельная фоновая очистка пока не настроена.
- Подписанные ссылки воспроизведения действуют 15 минут. Для длинного трека после истечения ссылки может понадобиться снова нажать play.
- При конфликте версии или сетевом сбое плейлист перечитывается; неподтверждённое изменение может потребоваться повторить. Долговечной офлайн-очереди пока нет.

SQL-проверки находятся в [tests](../tests) и предназначены для отдельной тестовой базы. Настройка SMTP, резервного копирования, мониторинга и проверка под нагрузкой относятся к подготовке production-окружения.


## Регистрация и профиль

Приложение поддерживает вход по логину или email и паролю, подтверждение почты, вход по ссылке и восстановление пароля. Имя (`display_name`) и цвет аватара (`avatar_color`) хранятся в метаданных Supabase Auth и используются только для отображения, не для прав доступа. Для облачного Auth установи минимальную длину пароля 8 символов; локальная конфигурация уже содержит это ограничение.

В Auth → URL Configuration добавь точные Redirect URLs для используемых адресов:

- `https://myroom-tawny.vercel.app/room?account=profile`
- `https://myroom-tawny.vercel.app/room?account=recovery`
- `http://127.0.0.1:3000/room?account=profile`
- `http://127.0.0.1:3000/room?account=recovery`

Site URL опубликованного приложения: `https://myroom-tawny.vercel.app/`. Для других доменов нужны соответствующие адреса. Не выключай подтверждение почты ради тестирования. Для регистрации произвольных пользователей настрой собственный SMTP: встроенный почтовый сервис может ограничивать адресатов и частоту отправки.

Проверка с реальным почтовым ящиком: регистрация → подтверждение письма → вход → изменение имени и цвета → перезагрузка → выход → восстановление пароля → вход с новым паролем. Не используй реальные пароли в отчётах и скриншотах.


## Вход через Google

В Google Cloud для MyRoom создан отдельный проект `fluted-alloy-512916-u3`. Для завершения подключения настрой Google Auth Platform и создай OAuth-клиент типа Web application:

- Homepage: `https://myroom-tawny.vercel.app/`
- Authorized JavaScript origin: `https://myroom-tawny.vercel.app`
- Authorized redirect URI: `https://tpjqioqxvvytmgfztldn.supabase.co/auth/v1/callback`

Client ID и Client Secret добавляются только в Supabase → Authentication → Sign In / Providers → Google. Секрет не помещать в исходники, переменные NEXT_PUBLIC или README. Приложение запрашивает стандартные данные для входа; доступ к Gmail и Google Drive не нужен. Не отключать проверки nonce и email.

Для Google не требуется SMTP. Для регистрации по email и восстановления пароля почтовый сервис всё ещё нужен. В тестовом статусе Google доступ может быть ограничен тестовыми пользователями; перед общим запуском нужно проверить статус аудитории и требования Google.
