# 7. Стек и архитектура

## Стек

| Область | Решение |
|---|---|
| Приложение | Next.js App Router, React, TypeScript |
| Стили | Tailwind CSS |
| Сцена | PNG-спрайты, CSS-позиционирование и слои, image-rendering: pixelated |
| Состояние | React Context + reducer, вычисляемые селекторы |
| Хранилище | localStorage через интерфейс репозитория |
| Валидация | Схемы, например Zod; библиотека подключается при реализации |
| Проверки | Vitest, React Testing Library, Playwright |

Next.js, React, TypeScript и Tailwind уже подключены. Остальное — план реализации. Аккаунты, серверная БД и библиотеки графов не нужны для MVP.

## Ответственность слоёв

- Domain: экономика, целостность покупок, проверка footprint и размещений.
- Application: начисление подтверждённого интервала, покупка, размещение, импорт и сброс.
- Infrastructure: localStorage, миграции, валидация, часы и блокировка вкладок.
- UI: страницы, сцена, карточки, формы и доступное управление.

UI не меняет баланс напрямую. Таймер и локальное хранилище работают на клиенте после загрузки сохранения. Каталог имеет стабильные ID.

## Команда изменения состояния

1. Получить право записи и прочитать последнюю revision.
2. Проверить команду и ссылки на каталог/инвентарь.
3. Вычислить целостное следующее состояние.
4. Проверить инварианты.
5. Увеличить revision и записать один JSON-снимок.
6. Только после успешной записи обновить подтверждённое UI-состояние.

Покупка списывает баланс и добавляет Purchase + InventoryItem в одной записи. Размещение меняет только позиции. Повтор purchaseId возвращает результат без нового списания.

## Таймер и вкладки

Web Locks API предоставляет эксклюзивную блокировку владельца записи на весь период владения. Вкладка без блокировки — только чтение; storage/BroadcastChannel сообщают об обновлениях. revision выявляет устаревшие состояния, но не заменяет блокировку.

После сбоя владельца блокировка освобождается браузером; следующий владелец читает последнее сохранение и запускает новую опорную отметку. Ранее прошедшее время не компенсируется. При отсутствии Web Locks безопасный режим чтения объясняет ограничение.

ActivityTracker читает visibility/focus и монотонные интервалы, отбрасывает разрывы более 5 секунд. Начисление и учёт времени сохраняются атомарно. При ошибке записи неподтверждённый интервал не считается заработанным.

## Дальнейшая синхронизация

Будущее облако потребует авторизации, правил конфликтов, серверного учёта и контроля доступа. Это отдельный этап, а не простая замена localStorage.
