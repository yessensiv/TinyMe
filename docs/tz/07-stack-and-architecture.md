## 7. Технический стек и архитектура

### 7.1. Стек

| Область | Решение |
|---|---|
| Приложение | Next.js, App Router |
| Язык | TypeScript |
| Стили | Tailwind CSS |
| Переходы | framer-motion |
| Аватар и комната | Слоистый SVG |
| Граф | d3-force для расчёта раскладки + собственный SVG-рендерер |
| Состояние MVP | React Context + reducer, вычисляемые селекторы |
| Хранение | localStorage через интерфейс репозитория |
| Проверка данных | Схемы валидации, например Zod |
| Тесты | Vitest, React Testing Library, Playwright |
| Размещение | Vercel |

Версии зависимостей фиксируются в lock-файле при старте разработки.

### 7.2. Архитектурные слои

1. **Domain:** XP, уровни, вехи, ограничения и расчёты.
2. **Application:** сценарии завершения задачи, выдачи наград, импорта.
3. **Infrastructure:** localStorage, миграции, будущий Supabase.
4. **UI:** страницы, формы, SVG и граф.

Бизнес-правила не размещаются непосредственно в обработчиках компонентов.

### 7.4. Сохранение выполнения задачи

Одна команда:

1. Проверяет, что задача ещё не завершена.
2. Создаёт достижение.
3. Пересчитывает XP и уровни.
4. Создаёт новые вехи и открытия.
5. Формирует целостное новое состояние.
6. Сохраняет его одной записью.
7. Показывает подтверждение и анимацию.

При ошибке записи интерфейс сохраняет прежнее подтверждённое состояние.

Для нескольких вкладок используются номер ревизии и событие `storage`. При внешнем обновлении данные перечитываются; одновременное редактирование блокируется либо явно требует обновления состояния.

### 7.5. Подготовка к Supabase

- UI работает через интерфейс хранилища.
- В будущем добавляется реализация с авторизацией и серверным хранением.
- Локальные ID сохраняются при переносе.
- Для серверных таблиц предусматривается принадлежность пользователю.
- Политики доступа, конфликты синхронизации и перенос гостевого профиля проектируются отдельным этапом.

Замена localStorage на Supabase не считается простой сменой SDK: она добавляет новые сценарии и требования к безопасности.
